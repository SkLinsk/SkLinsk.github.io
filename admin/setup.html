连接 GitHub 登录

编辑器可先用于本机草稿和预览。要发布文章，需要配置你自己的授权服务。整个过程不需要把密钥发给他人。

1. 部署授权服务

登录 Cloudflare，在 Workers 中创建一个服务。把仓库 auth/worker.mjs 的内容粘贴到服务编辑器并部署。记下 HTTPS 服务网址，例如 https://sklinsk-writer-auth.你的账户.workers.dev 。

2. 注册 GitHub App

在 GitHub App 设置 创建自己的应用。Homepage URL 填 https://sklinsk.github.io/admin/，Callback URL 填上一步服务网址后接 /callback 。关闭 Webhook。仅授予网站仓库 Contents 的 Read and write、Actions 的 Read-only 权限；Metadata 保持默认。应用仅允许安装到自己的账号。

创建后，在 Install App 中只选择 SkLinsk.github.io 仓库。复制应用的 Client ID（不是 App ID），并生成 Client secret。

3. 填写服务配置

回到 Cloudflare Worker → Settings → Variables and Secrets。添加以下配置并重新部署：

  • GITHUB_CLIENT_ID：应用的 Client ID。
  • GITHUB_CLIENT_SECRET：应用的 Client secret，类型必须为 Secret。
  • ALLOWED_ORIGIN：https://sklinsk.github.io
  • ALLOWED_LOGIN：SkLinsk

服务的 /health 地址应返回 ready: true。不要把 Client secret 放进仓库、文章或写作页。

4. 登录与发布

返回写作页，展开“首次配置”，粘贴授权服务网址并保存，再点击 GitHub 登录。首次使用会跳转到 GitHub 授权窗口。完成后即可创建、修改和发布文章。

文章与草稿

本机草稿保存在当前浏览器，不会自动跨设备同步。发布后 Markdown、网页、图片和列表一起进入公开仓库，部署状态会显示在写作页。修改历史文章时不会重新生成 PDF，因此新的阅读页会暂时隐藏旧 PDF 入口。退出或关闭页面会清除内存中的登录凭据；下次发布重新登录。

若网站提供了新配置，清理浏览器站点数据会一并删除本机草稿，建议先导出 Markdown。Markdown 导出不包含图片文件，图片需自行留存。

实现与维护

公共阅读页不加载写作后台脚本。授权服务源码和编辑器源码都在仓库中。文档渲染以 Markdown 为主，数学公式沿用网站现有的 KaTeX 字体与样式，不依赖 Hexo。
